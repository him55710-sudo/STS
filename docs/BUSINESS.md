# STS 사업 모델 — 차별화와 수익 구조

> **STS = 스타일을 공유하는 소셜 플랫폼. 사고 싶어졌을 때만 상거래가 나타난다.**
>
> 이 문서는 돈이 어떻게 도는지를 설명한다. **어디까지 보여도 되는지는**
> [`COMMERCE_INTEGRITY.md`](COMMERCE_INTEGRITY.md)가 정하며, 충돌하면 그쪽이 이긴다.

## 1. 코어 루프

```
크리에이터가 콘텐츠 발행 (직접 업로드 또는 TikTok 임포트)
   ↓
STS AI가 착장 속 오브젝트를 탐지하고 상품 후보를 제시
   ↓
크리에이터가 exact(동일 상품) / similar(유사 상품)를 확정   ← 확정 없이는 exact가 저장되지 않는다
   ↓
뷰어는 평소처럼 콘텐츠를 감상한다 — 가격도, 구매 버튼도 보이지 않는다
   ↓
사고 싶어진 뷰어가 사진 속 물건을 탭 → Product Sheet → 판매처 이동
   ↓
전환이 통보되면 수수료를 [크리에이터 : STS]로 배분하고 원장에 기록
   ↓
실적 데이터로 신규 브랜드 제휴 영업 → 카탈로그·수수료 풀 확대
```

핵심 플라이휠: **좋은 콘텐츠가 신뢰를 만들고, 신뢰가 구매 의도를 만들고,
구매가 크리에이터를 남게 한다.** 수수료를 앞세워 이 순서를 뒤집으면 피드가 카탈로그가 되고
플라이휠 자체가 멈춘다 — 그래서 무결성 지표를 성장 지표보다 먼저 본다.

### AI가 대신하는 것과 크리에이터가 반드시 하는 것

| | 담당 |
|---|---|
| 오브젝트 탐지·후보 검색·색/속성 추출 | **AI** (크리에이터 작업 0) |
| "이게 정확히 그 상품인가"의 최종 판단 | **크리에이터** (양보 불가) |

exact 링크는 DB 제약 `exact_requires_verifier`(`relationship <> 'exact' or verified_by is not null`)로
확정자 없이는 저장 자체가 불가능하다. AI가 아무리 확신해도 기본값은 `similar`다.
**"AI가 다 해준다"는 마케팅 문구는 쓰지 않는다** — 잘못된 exact 하나가 신뢰 전체를 깎는다.

## 2. 차별화

| | Pinterest / 일반 제휴 링크 | STS |
|---|---|---|
| 상품 태깅 주체 | 판매자·브랜드가 카탈로그 연동 | **AI가 후보까지 만들고, 크리에이터가 확정** |
| 인터랙션 | 핀 저장 → 상품 상세 이동 | **사진 속 물건 자체를 탭** (태그 아이콘 탐색 불필요) |
| 기본 화면 | 상품 카드·가격이 상시 노출 | **가격·CTA·상품 수 배지 없음.** 의도가 나타나야 등장 |
| 크리에이터 수익 | 외부 제휴 링크를 직접 관리 | **플랫폼 내장 배분** — 링크 작업 0초 |
| 어트리뷰션 | 크리에이터 개인 링크에 의존 | `/go/[offerId]` 단일 관문 + 1st-party 쿠키 (로그인 불필요) |
| 데이터 자산 | 저장 기반 취향 그래프 | **객체 단위 구매 의도 그래프** |

태깅 비용이 낮으므로 롱테일 크리에이터(팔로워 1천~10만)까지 수익화 가능하다 —
기존 제휴 플랫폼이 커버하지 못하는 공급층이다.

## 3. 수익 아이템 (단계별)

1. **제휴 수수료 스프레드 (현재)** — 제휴 네트워크/브랜드 수수료 중 플랫폼 몫. 코어.
2. **Sponsored Similar** — 브랜드가 "비슷한 스타일" 슬롯 노출을 구매.
   **광고는 similar 슬롯에만 들어가고 "Sponsored" 라벨이 반드시 붙는다.
   착용 상품(exact)은 어떤 금액으로도 광고가 될 수 없다.**
3. **크리에이터 Pro 구독** — 상세 전환 분석, 정산 우선 지급, 커스텀 숍 페이지.
4. **브랜드 대시보드 (B2B SaaS)** — "어떤 착장 맥락에서 우리 상품이 탭·구매되는가".
5. **트렌드 리포트/API** — 객체 단위 구매 의도 데이터셋 라이선스.

### 수익 배분

크리에이터 몫은 **설정값**이다 (`NEXT_PUBLIC_CREATOR_SHARE`, 기본 `0.70`).
UI 문자열과 정산 계산 모두 `lib/commerce/revenue.ts` 한 곳을 거치며,
**"70%"를 코드나 화면에 하드코딩하지 않는다.** 배분율 변경은 환경변수 한 줄이다.

분배 금액은 서버가 계산해 전달하고, DB는 합계 불변식(`creator + platform = gross`)을
check 제약으로 강제한다.

### 정산 상태 전이

```
pending ──(제휴사 확정)──> confirmed ──(보류 30일 경과)──> payable ──> paid
   └──────────────(반품·취소)──────────────> reversed
```

`reversed` 이후 다시 `confirmed`로 되돌리려는 통보는 무시된다 (`ignored_downgrade`).

## 4. 크리에이터 온보딩

- **링크 설정**: 없음 (AI가 후보를 만들고, 크리에이터는 exact/similar만 확정)
- **수수료 계약**: 없음 (가입 = 표준 배분 동의)
- **TikTok 임포트**: 기존 영상을 가져와 초기 콘텐츠 공백을 메운다.
  임포트는 **항상 드래프트**로 들어오며 자동 발행되지 않는다.
- **정산 확인**: 비공개 Creator Studio · 수익 페이지.
  **공개 프로필에는 수수료율·배분율·수익을 노출하지 않는다** — 공개 표면의 크리에이터는
  판매자가 아니라 사람이어야 한다.

## 5. 사기 방지 (결정적 규칙, ML 없음)

수익이 걸린 순간 남용이 따라온다. 규칙은 전부 명시적 임계값과 순수 비교이며,
오탐이 나도 왜 걸렸는지 한 줄로 설명할 수 있어야 한다 (`lib/integrity/fraud.ts`).

| 규칙 | 판정 | 조치 |
|---|---|---|
| `duplicate_callback` | 동일 전환 재전송 | info 기록 (중복 수익은 DB 제약이 이미 차단) |
| `click_burst` | 60초 내 같은 오퍼 5회 이상 | warn 기록 |
| `self_click` | 크리에이터가 자기 콘텐츠 상품 클릭 | warn 기록 |
| `conversion_replay` | 90일 초과 과거 전환 / 같은 id에 다른 금액 | warn · critical |

**플래그는 사용자를 차단하지 않는다.** 기록하고 정산 검토 대상으로 표시할 뿐이다 —
정상 사용자가 링크를 두 번 눌렀다고 구매를 막으면 그게 더 큰 손해다.

## 6. 감시 지표

성장 지표(GMV·전환)보다 **먼저** 보는 4개 지표. 나빠지면 제품이 카탈로그로 변질되는 중이다.

| 지표 | 권장 | 의미 |
|---|---|---|
| 오가닉 콘텐츠 비율 | ≥ 40% | 평범한 일상 콘텐츠가 충분히 남아 있는가 |
| 상품 밀집 비율 | ≤ 50% | 피드가 카탈로그로 변질되고 있지 않은가 |
| 숨김률 | ≤ 5% | 상거래 노출 과잉의 조기 신호 |
| 크리에이터 유지율 | ≥ 30% | 수익만 좇는 설계는 이 지표를 떨어뜨린다 |

표본이 없으면 **0%가 아니라 "데이터 없음"** 으로 표시한다. 관측되지 않은 것과 나쁜 것은 다르다.
