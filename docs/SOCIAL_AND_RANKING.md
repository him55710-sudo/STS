# STS 소셜 플랫폼 + 추천 v1 (Phase 5)

> **Date**: 2026-08-14 · **Branch**: `claude/sts-production-gap-audit-8uhzw5`
> 감사 문서 Gap 4(소셜 영속화)와 Gap 13(피드 추천)을 닫는다. **DM은 범위 밖이다.**

## 1. 소셜 액션의 프로덕션 진실 = 서버

| 액션 | 테이블 | 비고 |
|---|---|---|
| follow | `follows` | Phase 1 |
| post_like | `post_likes` | Phase 1 |
| post_save | `post_saves` | Phase 1 (본인만 조회) |
| product_save | `product_saves` | Phase 1 (본인만 조회) |
| comment | `comments` | **이번에 UI 활성화** |
| share | `post_shares` | **신규** — 공유 수는 공개 지표 |
| 관심없음/숨기기 | `content_feedback` | **신규** — 본인만 조회 |
| 조회·오브젝트 탭 | `interaction_events` | **신규** — 약한 취향 신호 |

localStorage는 더 이상 이 액션들의 진실이 아니다. 로그인 상태에서 모든 토글은
서버에 기록되고(낙관적 UI + 실패 시 롤백), 취향 프로필은 **오직 서버 데이터**로 계산된다.
localStorage에 남는 것은 데모 모드 콘텐츠와 UI 편의 캐시뿐이다.

**프라이버시 설계** (SQL로 실측 검증):
- 부정 피드백(`content_feedback`)과 상호작용 신호(`interaction_events`)는 **본인만** 읽는다.
  크리에이터가 "누가 내 글을 숨겼는지" 볼 수 있으면 위축 효과가 생긴다 — 실측: 크리에이터 관점 조회 0행.
- 공유 수·댓글은 공개 지표다 (누가 아니라 몇 번).
- 타인 명의 기록은 RLS가 거절한다 (실측 확인).

## 2. 안정적 공개 URL + 공유

모든 게시물은 `/post/{id}`라는 안정적 공개 URL을 갖는다 (`postPublicUrl()`).

공유 동작:
1. `navigator.share()`가 있으면 네이티브 시트 → 성공 시 `post_shares(method='web_share')` 기록
2. 없으면 클립보드 복사 폴백 → `post_shares(method='copy')` + "링크를 복사했어요" 안내
3. **사용자가 시트를 취소하면(AbortError) 아무것도 기록하지 않는다** — 가짜 공유 수를 만들지 않는다

`post_share` 이벤트도 함께 추적된다. 브라우저 실측: 복사 폴백 동작 + `http://localhost:3000/post/post-look6` 복사 확인.

## 3. 죽은 컨트롤 정리

크리에이터 프로필의 "메시지" 버튼은 동작하지 않는 채로 남아 있었다 →
`disabled` + **"메시지 · 준비 중"** 라벨로 교체했다 (실측: `disabled=true`). DM은 구현하지 않았다.

## 4. 피드

- **Following**: 시간 역순. 팔로우한 크리에이터만, 숨긴 게시물 제외. (`rankFollowingFeed`)
- **For You**: 결정적 랭킹 v1. (`rankFeed`)

### 취향 프로필 — `lib/recommendation/taste-profile.ts`

신호 가중치:

| 신호 | 가중치 | | 신호 | 가중치 |
|---|---|---|---|---|
| view | 0.1 | | outbound | 5 |
| object_tap | 1 | | purchase | **10** |
| card_open | 1.5 | | follow | 4 |
| post_like | 1.5 | | share | 3 |
| post_save | 2 | | product_save | 3 |
| | | | **hide** | **−5** |

집계 차원: **category · brand · color · price_band · creator · style**.
색상은 hex 그대로가 아니라 인지 버킷(`neutral-black`·`blue`·`green`…)으로,
가격은 절대 금액이 아니라 구간(`budget`/`mid`/`premium`/`luxury`)으로 학습한다 — 일반화를 위해.

- **시간 감쇠**: 반감기 30일. 오래된 취향이 새 취향을 가리지 않는다.
- **정규화**: 차원별 최대 절대값으로 나눠 −1~1. 절대 크기가 아니라 상대 선호를 쓴다.
- **콜드 스타트**: 긍정 가중치 합 < 5면 `isCold` — 개인화를 신뢰하지 않는다.

### 랭킹 — `lib/recommendation/feed-ranker.ts`

| 축 | 가중치 | 내용 |
|---|---|---|
| taste | 0.24 | 카테고리/브랜드/색상/가격대/스타일 적합도 |
| creator | 0.22 | 팔로우(0.55) + 과거 상호작용(0.45) |
| quality | 0.20 | 참여율 — **커머스 밀도를 보지 않는다** |
| freshness | 0.18 | 반감기 3일 |
| novelty | 0.10 | 이미 본 게시물 감점 |
| **commission** | **0.03** | 수수료 (상한 10%) |
| (페널티) | −0.15까지 | 구매 불가 링크 비율 |

**불변식**:
1. **수수료는 주요 요소가 될 수 없다.** 가중치가 다른 모든 축보다 작고 10%에서 절단되며,
   로드 시점 단언이 이를 강제한다 (가중치를 잘못 바꾸면 모듈이 즉시 실패).
   실측: 수수료 90% + 오래되고 반응 없는 게시물 < 수수료 0% + 신선하고 반응 좋은 게시물.
2. **숨김은 감점이 아니라 제외.** 사용자가 아니라고 했으면 아니다.
3. **콜드 스타트에서도 회피 신호는 즉시 적용된다.** 긍정 개인화만 억제한다
   (초기 개발 버전은 콜드일 때 "관심 없음"을 무시했다 — 테스트가 잡아 수정).
4. **모든 게시물이 쇼퍼블로 보이지 않는다.** 품질 점수가 상품 밀도와 무관하고,
   다양성 후처리가 (a) 같은 크리에이터 연속과 (b) 상품 밀집 게시물 4연속을 끊는다.
   상품이 하나도 없는 순수 콘텐츠도 동등하게 경쟁한다.
5. **완전 결정적**: 무작위성 없음. 동점은 `postId` 오름차순. 같은 입력 → 같은 순서.

## 6. 남은 한계

- **랭킹은 클라이언트에서 계산된다.** 후보 수가 커지면 서버 `GET /api/feed`로 옮겨야 한다
  (랭커가 순수 함수라 이동 비용은 낮다). 페이지네이션도 그때 함께.
- **댓글은 서버 게시물(uuid)에만** 달 수 있다 — 시드 데모 콘텐츠는 대상이 아니며 UI가 그렇게 안내한다.
- 대댓글·멘션·알림은 없다. 신고/차단도 이번 범위 밖(감사 문서 Gap 14의 나머지).
- `purchase` 신호는 현재 RLS가 허용하는 범위(내 클릭 ↔ 확정 전환)에서만 판정된다.
  구매자 관점 전환 뷰가 생기면 더 정확해진다.
- 익명 사용자는 취향 프로필을 갖지 않는다 (프로필을 귀속시킬 대상이 없다) — 인기·신선도 피드를 본다.
